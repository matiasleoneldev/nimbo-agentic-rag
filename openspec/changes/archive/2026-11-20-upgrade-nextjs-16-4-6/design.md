# Design

## Context

- `frontend/package.json` pins `next` and `eslint-config-next` exactly at 16.4.1. That is why `npm audit` reports the fix (16.4.6) as outside the declared range: `npm audit fix` without `--force` can never move an exact pin.
- `next.config.ts` turns on `cacheComponents` and `partialPrefetching`. The app is a single page (`app/layout.tsx`, `app/page.tsx`, `app/chat.tsx`, `app/i18n.ts`). Its only request-time API is `headers()`, to read `accept-language`.
- `eslint.config.mjs` imports `eslint-config-next/core-web-vitals` and `eslint-config-next/typescript`. `eslint-config-next` 16.4.6 depends on `@next/eslint-plugin-next` 16.4.6 and on `typescript-eslint ^8.56.0`.
- `npm run typecheck` runs `next typegen` before `tsc`, so route types are regenerated by the installed `next`.
- The Playwright web server runs `npm run build` (a production build with Cache Components) and `next start` on `127.0.0.1:3100`. The CI `frontend` job runs `npm ci`, lint, typecheck and the E2E suite on every pull request.
- The agent upgrade nudge lives in `next/dist/lib/upgrade/nudge.js`. It only stops commands run by a detected AI agent, and returns early in CI.

## Goals / Non-Goals

**Goals:**
- `npm audit` in `frontend/` lists no `next` advisory.
- The diff touches only `package.json`, `package-lock.json` and, if regenerated, `AGENTS.md`.

**Non-Goals:**
- Adopting Next "Future Defaults", or any other config change offered by the new version.
- Upgrading `react`, `react-dom`, Tailwind, Playwright, TypeScript or `@types/*`.
- Changing the CI workflow.
- Turning off `cacheComponents`. It is not needed once the version is fixed, and turning it off would change rendering behavior.

## Decisions

### Upgrade both Next packages in one install, with exact pins
Run `npm install --save-exact next@16.4.6 eslint-config-next@16.4.6` in `frontend/`. Moving them together keeps the lint rules on the same framework version. `--save-exact` keeps the current pinning style. Alternative: `next upgrade --agent` (rejected in the proposal). Alternative: change to `^16.4.6` and let `npm audit fix` move it. Future installs could then pick up unreviewed framework releases.

### Refresh the transitive lint tooling with a non-forced `npm audit fix`
After the bump, `npm audit fix` without `--force` moves only transitive packages within ranges already declared. Today that is `typescript-eslint` 8.71.2 → 8.73.0 and its `@typescript-eslint/*` and `minimatch` dependents. `package.json` keeps its ranges. Alternative: leave the lock file as `npm install` writes it. The dev-only `minimatch` advisory would stay in the audit output and hide future real findings. Alternative: delete and regenerate the whole lock file. That would also float every unrelated transitive dependency, which makes the diff impossible to review.

### Dependencies
No new dependency. `next` and `eslint-config-next` already exist and only change version. The lock-file refresh changes versions of existing transitive packages only.

### Verification is the existing suites
Lint, typecheck and the E2E suite already cover the surface this upgrade can break. Lint covers the ESLint rule set. Typecheck covers the generated route types (`LayoutProps<"/">`) and the `next` type exports. The E2E suite covers the production build with Cache Components, prefetching and the streamed chat UI on phone and desktop. No new tests are added: the change adds no behavior to trace.

## Risks / Trade-offs

- [The patch release changes Cache Components or prerendering behavior and the build fails, or `instant = false` / `generateMetadata` behave differently] → `npm run test:e2e` builds for production and fails. Read the Next 16.4.5/16.4.6 release notes before fixing anything. If the fix goes beyond a version bump, stop and widen this change.
- [`eslint-config-next` 16.4.6 adds or tightens a rule and `npm run lint` fails] → Fix the code if the rule is right. Never disable the rule globally to get a green run.
- [`npm audit fix` touches more than the lint tooling] → Read the `package-lock.json` diff. If it moves runtime packages unrelated to this change, revert the lock file and refresh only `typescript-eslint` with `npm update typescript-eslint`.
- [The new `next` rewrites `frontend/AGENTS.md`] → Commit the regenerated block with the bump, as the file itself says to.
- [The nudge still fires locally] → It should not, since 16.4.6 has no known advisory. If a later advisory appears, a nudge is the expected signal for the next bump, not a bug in this change.

## Migration Plan

Merge a pull request whose CI `frontend` job is green. To roll back, revert the commit: `package.json` and `package-lock.json` go back to 16.4.1 together.
